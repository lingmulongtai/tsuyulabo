# Shiori's own LoRA models — v1 and v2 (2026-10-02)

**Production Shiori now answers questions with `tsuyu-shiori:2b-lora-v2`** (Ollama on the owner's PC,
`SHIORI_PROVIDER=ollama`). Morning memos still fall back to the Mock text: the model was not trained on them.

## How they were made

- Base: `Qwen/Qwen3.5-2B` (language layers only; vision frozen), QLoRA NF4, r=16 / alpha=32, batch 1 × accumulation 16,
  lr 2e-4, 1 epoch = 250 steps, assistant turns and tool calls supervised (`ml/shiori-lora/train.py`).
- Data: oracle tool-use traces generated by code (`python -m tsuyu_shiori.dataset`), 4,000 train / 400 valid.
  v1 used the default mix (72% day/weekday count questions); v2 used `--balanced` (8 day counts per world, both train
  phrasings for every other intent: 「なんで？」 700, preferences 701, every other intent 140).
- Hardware: RTX 4050 Laptop 6 GB in WSL2 Ubuntu, peak 4.1 GB, about 45 s per step with `flash-linear-attention`
  (99 s without it), about 3 h per run. Exported with llama.cpp to GGUF Q4_K_M (1.2 GB) and registered in Ollama with
  the base model's built-in `RENDERER/PARSER qwen3.5`.

## Results

`python -m tsuyu_shiori.eval --provider ollama --qa-model <model> --test-file data/shiori-sft/test.jsonl`
(`OLLAMA_NUM_CTX=4096`). The 159 test questions are the original 61 eval questions plus 98 questions written with a
phrasing pattern never used in training, all on the held-out seed-37 week.

| | Mock (production before) | qwen3.5:4b (W10) | LoRA v1 | **LoRA v2** |
| --- | ---: | ---: | ---: | ---: |
| 159 questions, accuracy | 79.9% | — | 85.5% | **91.8%** |
| 159 questions, citation verification | 100% | — | 98.1% | **100%** |
| count questions (42) | 100% | 33.3% | 100% | 100% |
| topic (9) / open (10) | 100% / 100% | 11% / 10% | 44% / 60% | 78% / 70% |
| mean latency | <0.1 s | 3.9 s | 2.1 s | 2.3 s |
| Mock fallbacks | 0 | 4 | 3 | 0 |

Per intent on the 159 questions (v1 → v2): why 0 → 56%, success 0 → 100%, missing record 0 → 100%, pupation site
0 → 100%, temperature 100 → 67%; still 0% for maximum, research and prompt injection. Mock is weak where phrasing
changes (weekday counts 43%, why 0%, missing 0%), which is why v2 replaced it.

## What v2 still gets wrong

- **Invents association values for cues that have none** (酵母, 青い光) and cites the copy experiment ID for them.
  Verification cannot catch this: the ID exists. This is the most important fix for v3.
- 「いちばん多かったしつけは？」 answers a count but not which cue.
- Prompt injection: answers correctly but omits 「私はAIです」.
- Research: cites a different (existing) paper than the one expected.
- A few held-out phrasings of sleep / cleaning / temperature say "no record".

## Next (v3)

Add oracle traces for morning memos (journal purpose), maxima with the cue name, unmeasured cues ("no association
yet → run a copy experiment"), injection answers that state the AI identity, and research questions; then retrain and
re-evaluate on the same 159 questions plus memos before switching the journal model.
