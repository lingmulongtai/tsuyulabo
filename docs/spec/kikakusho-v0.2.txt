 ツユラボ
 本物のハエの脳で育つ。毎週1匹、卵から育てる育成研究ゲーム。
 朝・昼・夜にごはんを作り、パズルでしつけ、1週間で卵を成虫まで育てる。日曜の夜は羽化と研究発表会。育てた子は研究チームに加わり、フレンドと競い、次の世代へつながっていく。
 名前の由来：ショウジョウバエの学名 Drosophila は、ギリシャ語で「露を好むもの」。
 キャラクター ツユを描き直した。光と影、質感、本物のハエの特徴を入れたデザインに。
 1週間サイクル 月曜に卵、日曜に羽化。毎週1匹を育てきる、ポケモンスリープ型の研究ループに。
 ミニゲーム お世話はすべて数秒〜30秒のパズルに。実際に遊べるデモを2つ入れた。
 厳選と対戦 素質・特性・サブスキル・系統。フレンド機能と非同期の競技。
 課金とサーバー 通貨、パス、ショップ、法律面、サーバー構成と費用の目安を追加。
 ツユ（オス、野生型）。キャラクターは企画用の1パターン。

 日曜の夜の羽化が、1週間でいちばん盛り上がる瞬間。週のランクが高いほど、良い結果が出やすい。

 遊んでみて：羽化の演出
 さなぎがゆれて、光の色が白 → 青 → 金 → 虹と上がっていくほどアツい。虹まで行くと突然変異（めずらしい系統）が確定。
 ランクを変えると確率が変わる。1週間がんばったことが、そのまま「当たりやすさ」になるしくみ。確率はすべて公開する。
 本番では1週間に1回。お金を払って回すことはできない。

 性別 羽化で決まる（半々）。オスとメスで、使う脳の配線図が違う。 変わらない 本物 
 生まれつきの特性は、遺伝子が同じハエでも1匹ずつ曲がる方向にクセがある、という研究がもと。脳モデルのパラメータを少しずつずらして作る。このクセは親から子へ受け継がれにくいとされるので、ゲームでも遺伝しない（だから厳選に運が入る）。
 研究チーム（最大5匹）
 成虫をチームに入れると、時間ごとに材料としずくを集めてくる。量は、レベル、サブスキル、そして「何を好きに育てたか」で変わる。バナナ好きに育てた子はバナナをよく見つける。
 レベル上げ
 しずくと活動の経験でレベルが上がる。上限は素質の★で決まる。げんきは、あなたが「おやすみ」から「おはよう」までねると回復する。
 交配と次の世代
 2匹を選ぶと、次の週の卵ができる。白い目のように性別で伝わり方が変わる「伴性遺伝」も本物どおり。狙った系統を作るのが、コレクションの楽しみ。
 6 フレンドと競技
 ゲーム内のフレンド機能で、他の人の飼育室をのぞけて、競える。対戦はすべて非同期なので、時間を合わせる必要がない。
 フレンドでできること
 飼育室をのぞく フレンドのチームと、今週育てている子を見られる。 
 自慢の1匹とプロフィール 称号、背景、フレーム、研究ランク、図鑑の達成率を飾れる。自分をアピールする場所。 
 いいねと、おすそわけ 1日1回、材料を送れる。送った側にも研究ポイント。 
 お見合い フレンドの成虫と交配して、両方に卵が届く。 
 お知らせ 「ゆうきさんの子が、にじランクで羽化しました」 
 競技
 毎日 今日の回路
 全員に同じパズル。フレンドの中でタイムを競う。
 毎週末 迷路レース
 同じ迷路に、自分の成虫を送り出す。どこにどの匂いを置くかの作戦を立てると、脳のシミュレーションで走りが決まる。しつけと特性が効く。
 毎週 見た目コンテスト
 お題に合わせて、飾った飼育室と自慢の1匹を出す。フレンドの投票で決まる。
 あとで追加 なわばりずもう
 オスどうしの押し合い。本物のオスも、なわばりをめぐって小競り合いをする。
 競技の結果に、お金で買ったものは一切効かない。
 7 演出と音
 うまくいったときは、とにかく気持ちよく。期待度を色でそろえて、どの場面でも「来るぞ」がわかるようにする。
 場面 見た目 音と振動 
 マスを進む、タップ ぷよんと弾む、光の粒 一歩ごとに音程が上がる「ポッ」 
 パズルクリア 光の波が回路を走る、星が1つずつ出る 和音のアルペジオ 
 大成功 画面フラッシュ、しずくが弾ける、金色の文字 ファンファーレ、短い振動 
 羽化の予兆 さなぎがゆれる、光の色が上がる（白 → 青 → 金 → 虹） 色に合わせて音が上がる、振動が強くなる 
 突然変異、★5 シオリのカットイン、虹のバースト、図鑑登録のスタンプ 専用のジングル 
 研究発表会 ランクのバッジが落ちてくる、紙吹雪 ドラムロールから決め音 
 期待度の色は全部共通
 白 < 青 < 金 < 虹。ごはん、しつけ、羽化、発表会で同じ並び。一度覚えれば、どこでもドキドキできる。
 ときどき外れる予兆
 金まで行って止まることもある。外れがあるから、虹が出たときに盛り上がる。長い演出は2回目からスキップできる。
 作り方
 画面の演出はPixiJS（WebGL）のパーティクル、ツユの動きはRiveのアニメーション、音はWeb Audio。スマホアプリ版では振動も使う。

 11 AIを自分で作る
 既製品のAPIを呼ぶだけで終わらせない。ゲームの中身になるAIを6つ、最初から自分で作り、全部を数字で評価する。
 AI ゲームでの役割 自分で作るところ 評価のしかた 
 脳エンジン ツユの行動のもとになる神経活動を計算する スパイキング・ニューラルネットのシミュレータをPyTorchで一から書く。部分回路の切り出しも自作 既存の研究用モデルと同じ回路で結果を比べる。「砂糖でMN9、影でDNp01が反応する」を自動テスト 
 学習ルール しつけで好き・苦手が変わる ドーパミンでキノコ体のつながりが変わるルール。パズルの★を学習の強さに変換 しつけ後に匂いテストをして、好みが狙いどおり変わるか 
 個体差ジェネレーター 生まれつきの特性を作る 脳モデルのパラメータを分布からずらし、特性として読める形にする 同じ特性の個体が、同じ傾向の行動をするか 
 行動デコーダー 神経活動を「歩く・食べる・逃げる」などの行動とアニメに変える 分類モデルを学習（ロジスティック回帰 → 小さなニューラルネット）。学習データも自分で作る 正解率と混同行列。本物の配線とシャッフルした配線での差 
 研究員シオリ メモ、コーチ、発表会、「なんで？」 フレームワークに頼らないエージェントの処理、道具（ツール）の設計、根拠IDの検証、論文検索（RAG）、モデルの使い分け 育成記録から問題と正解を自動生成して正答率を測る。根拠の検証率と1回答あたりのコスト 
 パズル生成と難易度推定 毎日の問題を作り、ちょうどいい難しさにする 神経の経路から問題を自動生成し、ソルバーで解けることを確認。プレイ記録から解く時間を予測するモデル 予測した時間と実際の時間のずれ 
 評価はCIで自動
 プルリクエストのたびに、脳のテスト、デコーダーの正解率、シオリの正答率を計測してコメントする。下がったらマージしない。
 コストも自分で下げる
 シオリの日誌は夜にまとめて作り、軽いモデルを使う。将来は、日誌用の小さな言語モデルを自分で追加学習させて置き換える。

 14 サーバーと技術
 基本方針は「サーバーが正しさを決める」「重い計算は後ろに回す」「1匹ごとに持つデータは小さく」。
 アプリ（Next.js、TypeScript）
 画面はReact、ゲームの場面と演出はPixiJS、キャラの動きはRive。最初はWeb（PWA）、次にCapacitorでiOS・Androidアプリにする。
 操作を送る ／ 結果を受け取る（REST と WebSocket）
 ゲームAPI（FastAPI）
 ログイン確認、報酬の計算、パズルの答え合わせ、通貨の出し入れ。すべてサーバー側で決める。
 ジョブを積む（Redis のキュー）
 脳ワーカー
 部分回路のシミュレーション、迷路レースの計算、行動デコーダー
 シオリワーカー
 質問への回答、夜の日誌のまとめ作成、論文検索
 定期ジョブ
 日曜夜の発表会の集計、毎日の問題の配信、通知
 読む ／ 書く
 Postgres ＋ pgvector
 ユーザー、フレンド、個体、学習した重み、出来事の記録、通貨の台帳、論文
 Redis、ストレージ
 ランキング、回数制限、キュー。レースのリプレイと画像はストレージとCDN
 外部サービス
 ログイン Firebase Auth または Supabase Auth 
 課金 アプリ内課金とサブスクの管理に RevenueCat。レシートはサーバーで検証 
 通知 Firebase Cloud Messaging（「ごはんの時間です」） 
 LLM API経由。自前のゲートウェイで、モデルの使い分けとキャッシュをする 
 監視 Sentry（エラー）、Langfuse（LLM）、PostHog（遊ばれ方の分析） 
 ずるを防ぐしくみ
 時間はサーバーの時計で数える。端末の時計を進めても成長しない
 パズルは、サーバーが出した問題の番号と操作の記録を送り、サーバーで答え合わせする
 報酬と通貨の増減は、すべてサーバーの台帳に記録（複式の台帳で、有料通貨の残高も正確に）
 同じ操作の二重送信は無視する（操作ごとにIDをつける）
 脳の計算を安くするしくみ
 16万ニューロンの配線はみんなで共通。読み取り専用で、ワーカーのメモリに1回だけ載せる
 1匹ごとに保存するのは、生まれつきのパラメータ、学習で変わった重み、出来事の記録だけ
 普段は、匂い、逃避、食べる、といった部分回路だけを計算。同じ条件の結果はキャッシュ
 時間の経過はアプリを開いたときにまとめて計算。24時間動かし続けない
 将来は脳の計算をスマホ側（WebGPU）に移して、サーバー代を下げる
 段階ごとの構成と費用の目安
 段階 規模 構成 月額の目安 
 ポートフォリオ版 〜100人 Vercel、Cloud Run（APIとワーカー）、Neon などの小さなPostgres、Upstash Redis 0〜3,000円 ＋ LLM代 
 β版 〜3,000人 Cloud Run（常時1台）、Cloud SQL（小）、Redis、Cloud Scheduler、Sentry 1〜3万円 ＋ LLM代 
 正式版 数万人〜 Cloud Run の自動スケール、Cloud SQL の冗長化と読み取り専用コピー、CDN、脳の計算をスマホ側へ 利用者数しだい（1人あたりの費用を指標にする） 
 費用は目安で、実測して見直す。LLM代は、日誌を夜にまとめて作る、軽いモデル中心、質問回数の上限、で1人1日数円以内を目標にする。
 開発の流れ（CI/CD）
 docker compose up で、アプリ、API、ワーカー、Postgres、Redis が手元で動く
 GitHub Actions：型チェック、テスト、脳のテスト、AIの評価、画面の自動操作テスト（Playwright）
 リリース前に負荷試験（k6）
 コンテナを作って Cloud Run へ自動デプロイ。プルリクエストごとにプレビュー環境
 データの出どころ
 成虫の配線図を前処理して、部分回路ごとの小さな行列ファイルにする。版番号をつけて管理
 パズル生成や分析には DuckDB を使う
 配線図データは CC-BY。アプリ内と README に出典を明記
 睡眠などの生活データは最小限。使うかどうかは本人が選ぶ
