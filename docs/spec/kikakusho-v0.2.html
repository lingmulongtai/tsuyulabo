ツユラボ

本物のハエの脳で育つ。毎週1匹、卵から育てる育成研究ゲーム。

朝・昼・夜にごはんを作り、パズルでしつけ、1週間で卵を成虫まで育てる。日曜の夜は羽化と研究発表会。育てた子は研究チームに加わり、フレンドと競い、次の世代へつながっていく。

名前の由来：ショウジョウバエの学名 Drosophila は、ギリシャ語で「露を好むもの」。

  • キャラクターツユを描き直した。光と影、質感、本物のハエの特徴を入れたデザインに。
  • 1週間サイクル月曜に卵、日曜に羽化。毎週1匹を育てきる、ポケモンスリープ型の研究ループに。
  • ミニゲームお世話はすべて数秒〜30秒のパズルに。実際に遊べるデモを2つ入れた。
  • 厳選と対戦素質・特性・サブスキル・系統。フレンド機能と非同期の競技。
  • 課金とサーバー通貨、パス、ショップ、法律面、サーバー構成と費用の目安を追加。

ツユ（オス、野生型）。キャラクターは企画用の1パターン。

名前「ツユラボ」の確認

ウェブ検索の範囲では、「ツユラボ」という名前のゲームやアプリは見つからなかった。

  • Instagramに @tsuyu.lab（「TSUYU」という香り・化粧品ブランド）がある。ジャンルは違うが、SNSのIDは別の形にする必要がある。
  • 「ツユ」単体は、音楽ユニット「TUYU（ツユ）」やめんつゆと検索でぶつかる。宣伝では「ツユラボ」の一語で使う。

1ゲームのしくみ

3つの時間の単位が重なっている。毎日のお世話が週の結果になり、週の結果がずっと残るコレクションになる。

毎日朝・昼・夜の3回、1回2〜3分
  • ごはんづくり（ブロックパズル）
  • しつけ（回路つなぎパズル）
  • そうじ、温度あわせ
  • 夜は「おやすみ」でいっしょにねる
毎週月曜に卵、日曜の夜に羽化
  • 1匹を卵 → 幼虫 → さなぎ → 成虫まで育てる

育成期間は1週間でコンパクトに。成虫になってからが長く遊べる本番、という二段構え。

5羽化と厳選

日曜の夜の羽化が、1週間でいちばん盛り上がる瞬間。週のランクが高いほど、良い結果が出やすい。

今週のランク：
シオリ「これは……！？」
デモなので何度でも
予兆の色結果確率

遊んでみて：羽化の演出

さなぎがゆれて、光の色が白 → 青 → 金 → 虹と上がっていくほどアツい。虹まで行くと突然変異（めずらしい系統）が確定。

ランクを変えると確率が変わる。1週間がんばったことが、そのまま「当たりやすさ」になるしくみ。確率はすべて公開する。

本番では1週間に1回。お金を払って回すことはできない。

生まれつきの特性は、遺伝子が同じハエでも1匹ずつ曲がる方向にクセがある、という研究がもと。脳モデルのパラメータを少しずつずらして作る。このクセは親から子へ受け継がれにくいとされるので、ゲームでも遺伝しない（だから厳選に運が入る）。

研究チーム（最大5匹）

成虫をチームに入れると、時間ごとに材料としずくを集めてくる。量は、レベル、サブスキル、そして「何を好きに育てたか」で変わる。バナナ好きに育てた子はバナナをよく見つける。

レベル上げ

しずくと活動の経験でレベルが上がる。上限は素質の★で決まる。げんきは、あなたが「おやすみ」から「おはよう」までねると回復する。

交配と次の世代

2匹を選ぶと、次の週の卵ができる。白い目のように性別で伝わり方が変わる「伴性遺伝」も本物どおり。狙った系統を作るのが、コレクションの楽しみ。

6フレンドと競技

ゲーム内のフレンド機能で、他の人の飼育室をのぞけて、競える。対戦はすべて非同期なので、時間を合わせる必要がない。

フレンドでできること

  • 飼育室をのぞくフレンドのチームと、今週育てている子を見られる。
  • 自慢の1匹とプロフィール称号、背景、フレーム、研究ランク、図鑑の達成率を飾れる。自分をアピールする場所。
  • いいねと、おすそわけ1日1回、材料を送れる。送った側にも研究ポイント。
  • お見合いフレンドの成虫と交配して、両方に卵が届く。
  • お知らせ「ゆうきさんの子が、にじランクで羽化しました」

期待度の色は全部共通

白 < 青 < 金 < 虹。ごはん、しつけ、羽化、発表会で同じ並び。一度覚えれば、どこでもドキドキできる。

ときどき外れる予兆

金まで行って止まることもある。外れがあるから、虹が出たときに盛り上がる。長い演出は2回目からスキップできる。

作り方

画面の演出はPixiJS（WebGL）のパーティクル、ツユの動きはRiveのアニメーション、音はWeb Audio。スマホアプリ版では振動も使う。

10研究員シオリ

ゲームの案内役で、研究の相棒。ツユの代わりに喋るのではなく、観察して、測って、説明する。

  • 朝の観察メモ夜のあいだの様子と、睡眠ボーナスを伝える。
  • しつけのコーチ「今週の迷路は匂いがカギ。バナナを覚えさせると有利かも」
  • 研究発表会の司会1週間をふり返り、ランクを発表する。
  • 「なんで？」に答えるツユのコピーで実験してから、根拠つきで答える。
  • 図鑑の解説本物の研究の話を、短く楽しく。
なんでこの子、りんご酢のときだけ離れていくの？
シ

火曜の夜、りんご酢の匂いのしつけで「にがいごはん」を3回覚えています。コピーで試したら、りんご酢から離れたのは20回中15回でした。

ゲーム内のモデルで測った結果です。本物のハエの気持ちではありません。

シオリの約束

  1. ツユの気持ちを代弁しない。「悲しんでいます」ではなく「動きが減っています」と言う。
  2. すべての説明に、記録か実験のIDをつける。実在しないIDの文は表示しない。
  3. 実験はいつもコピーで。本物のツユは変えない。
  4. シオリ自身がAIであることを隠さない。

11AIを自分で作る

既製品のAPIを呼ぶだけで終わらせない。ゲームの中身になるAIを6つ、最初から自分で作り、全部を数字で評価する。

AIゲームでの役割自分で作るところ評価のしかた
脳エンジンツユの行動のもとになる神経活動を計算するスパイキング・ニューラルネットのシミュレータをPyTorchで一から書く。部分回路の切り出しも自作既存の研究用モデルと同じ回路で結果を比べる。「砂糖でMN9、影でDNp01が反応する」を自動テスト
学習ルールしつけで好き・苦手が変わるドーパミンでキノコ体のつながりが変わるルール。パズルの★を学習の強さに変換しつけ後に匂いテストをして、好みが狙いどおり変わるか
個体差ジェネレーター生まれつきの特性を作る脳モデルのパラメータを分布からずらし、特性として読める形にする同じ特性の個体が、同じ傾向の行動をするか
行動デコーダー神経活動を「歩く・食べる・逃げる」などの行動とアニメに変える分類モデルを学習（ロジスティック回帰 → 小さなニューラルネット）。学習データも自分で作る正解率と混同行列。本物の配線とシャッフルした配線での差
研究員シオリメモ、コーチ、発表会、「なんで？」フレームワークに頼らないエージェントの処理、道具（ツール）の設計、根拠IDの検証、論文検索（RAG）、モデルの使い分け育成記録から問題と正解を自動生成して正答率を測る。根拠の検証率と1回答あたりのコスト
パズル生成と難易度推定毎日の問題を作り、ちょうどいい難しさにする神経の経路から問題を自動生成し、ソルバーで解けることを確認。プレイ記録から解く時間を予測するモデル予測した時間と実際の時間のずれ

評価はCIで自動

プルリクエストのたびに、脳のテスト、デコーダーの正解率、シオリの正答率を計測してコメントする。下がったらマージしない。

コストも自分で下げる

シオリの日誌は夜にまとめて作り、軽いモデルを使う。将来は、日誌用の小さな言語モデルを自分で追加学習させて置き換える。

面接で言えること

「生物の神経回路をもとにしたシミュレータ、自作の学習モデル、LLMエージェントを1つのゲームに組み込み、すべてを自動評価で管理しました」

研究パス（月額）

480円／月（仮）

  • 発表会の報酬が増える（見た目としずく）
  • シオリへの質問回数が増える
  • 脳ビューアの詳しい表示、写真のフィルター

  • 競技の結果に効くもの
  • お金で回すガチャ

  • 特定商取引法の表示、未成年の課金上限、確率の公開（無料の運要素も）

14サーバーと技術

基本方針は「サーバーが正しさを決める」「重い計算は後ろに回す」「1匹ごとに持つデータは小さく」。

アプリ（Next.js、TypeScript）

画面はReact、ゲームの場面と演出はPixiJS、キャラの動きはRive。最初はWeb（PWA）、次にCapacitorでiOS・Androidアプリにする。

操作を送る ／ 結果を受け取る（REST と WebSocket）

ゲームAPI（FastAPI）

ログイン確認、報酬の計算、パズルの答え合わせ、通貨の出し入れ。すべてサーバー側で決める。

ジョブを積む（Redis のキュー）

脳ワーカー

部分回路のシミュレーション、迷路レースの計算、行動デコーダー

シオリワーカー

質問への回答、夜の日誌のまとめ作成、論文検索

定期ジョブ

日曜夜の発表会の集計、毎日の問題の配信、通知

読む ／ 書く

Postgres ＋ pgvector

ユーザー、フレンド、個体、学習した重み、出来事の記録、通貨の台帳、論文

Redis、ストレージ

ランキング、回数制限、キュー。レースのリプレイと画像はストレージとCDN

外部サービス

ログイン
Firebase Auth または Supabase Auth
課金
アプリ内課金とサブスクの管理に RevenueCat。レシートはサーバーで検証
通知
Firebase Cloud Messaging（「ごはんの時間です」）
LLM
API経由。自前のゲートウェイで、モデルの使い分けとキャッシュをする
監視
Sentry（エラー）、Langfuse（LLM）、PostHog（遊ばれ方の分析）

ずるを防ぐしくみ

  • 時間はサーバーの時計で数える。端末の時計を進めても成長しない
  • パズルは、サーバーが出した問題の番号と操作の記録を送り、サーバーで答え合わせする
  • 報酬と通貨の増減は、すべてサーバーの台帳に記録（複式の台帳で、有料通貨の残高も正確に）
  • 同じ操作の二重送信は無視する（操作ごとにIDをつける）

脳の計算を安くするしくみ

  • 16万ニューロンの配線はみんなで共通。読み取り専用で、ワーカーのメモリに1回だけ載せる
  • 1匹ごとに保存するのは、生まれつきのパラメータ、学習で変わった重み、出来事の記録だけ
  • 普段は、匂い、逃避、食べる、といった部分回路だけを計算。同じ条件の結果はキャッシュ
  • 時間の経過はアプリを開いたときにまとめて計算。24時間動かし続けない
  • 将来は脳の計算をスマホ側（WebGPU）に移して、サーバー代を下げる

段階ごとの構成と費用の目安

段階規模構成月額の目安
ポートフォリオ版〜100人Vercel、Cloud Run（APIとワーカー）、Neon などの小さなPostgres、Upstash Redis0〜3,000円 ＋ LLM代
β版〜3,000人Cloud Run（常時1台）、Cloud SQL（小）、Redis、Cloud Scheduler、Sentry1〜3万円 ＋ LLM代
正式版数万人〜Cloud Run の自動スケール、Cloud SQL の冗長化と読み取り専用コピー、CDN、脳の計算をスマホ側へ利用者数しだい（1人あたりの費用を指標にする）

費用は目安で、実測して見直す。LLM代は、日誌を夜にまとめて作る、軽いモデル中心、質問回数の上限、で1人1日数円以内を目標にする。

開発の流れ（CI/CD）

  • docker compose up で、アプリ、API、ワーカー、Postgres、Redis が手元で動く
  • GitHub Actions：型チェック、テスト、脳のテスト、AIの評価、画面の自動操作テスト（Playwright）
  • リリース前に負荷試験（k6）
  • コンテナを作って Cloud Run へ自動デプロイ。プルリクエストごとにプレビュー環境

データの出どころ

  • 成虫の配線図を前処理して、部分回路ごとの小さな行列ファイルにする。版番号をつけて管理
  • パズル生成や分析には DuckDB を使う
  • 配線図データは CC-BY。アプリ内と README に出典を明記
  • 睡眠などの生活データは最小限。使うかどうかは本人が選ぶ
